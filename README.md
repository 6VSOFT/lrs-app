# 狼人杀自动法官（12 人 · 预女猎白）PWA — 无服务器版

12 位玩家各用手机加入同一个房间，由 App 担任法官：随机发身份、自动主持夜晚、结算死亡、统计投票、判定胜负。无需真人法官和实体牌，**也没有任何游戏服务器：所有数据都保存在玩家各自的手机上**。

## 工作原理
- **房主手机 = 法官**。创建房间的手机运行规则引擎、保管完整状态（含全部身份），并把每个人各自可见的内容推送给对方。
- **玩家手机之间点对点直连**（WebRTC，经 [PeerJS](https://peerjs.com) 公共信令服务建立连接；连通后游戏数据直接在手机间传输）。
- 每台手机把自己的令牌、昵称、最近一次看到的视图存在本机（`localStorage`）；房主手机额外存完整状态存档，**刷新页面可恢复**。
- 其他玩家只会收到：公共信息 + 仅属于自己的私人视图（自己的身份、狼队友、查验结果、女巫药剂/刀口、待办操作）。游戏结束才公布全部身份与记录。

| 部分 | 方案 |
|---|---|
| 前端 | React + TypeScript + Vite + Tailwind CSS |
| PWA | `vite-plugin-pwa`（Manifest + Service Worker，可添加到主屏幕、可离线打开页面） |
| 规则引擎 | `shared/engine/`：纯 TypeScript 有限状态机（`types.ts` 类型、`engine.ts` 规则、`views.ts` 视图过滤） |
| 房主端法官 | `src/hostcore.ts`（与网络解耦，可单元测试） |
| 网络 | `src/net.ts`（PeerJS / WebRTC，自动重连） |
| 托管 | 纯静态站点：Netlify / GitHub Pages / 任意静态托管 |

## 重要限制（无服务器的代价）
1. **房主手机必须保持本页面在前台、不锁屏、不关闭。** 房主掉线 = 游戏暂停（刷新后自动恢复，其他人自动重连）；房主手机损坏/清除数据 = 该局无法继续。应用会申请屏幕常亮（部分浏览器不支持，请在系统设置里把自动锁屏调长）。
2. **房主的手机里存有完整身份表。** 没有可信服务器就无法对房主保密，只能靠自觉：房主技术上能通过开发者工具查看。若需要对房主也保密，需要引入可信服务器（可告知，我再加回后端）。创建者在规则上无任何特权，也没有专属法官界面。
3. 首次建立连接需要联网访问 PeerJS 信令服务（0.peerjs.com）和 STUN/TURN；同一 Wi-Fi 下连接最稳定。个别网络（严格 NAT / 部分地区）可能连不通。
4. 玩家令牌存在浏览器本地；清除数据或换浏览器后无法找回座位。

## 本地运行
```bash
npm install
npm run dev      # http://localhost:5173
npm test         # 自动化测试
npm run build    # 类型检查 + 生产构建（含 PWA）
```
测试时用不同来源打开多个标签（例如 `localhost` 与 `127.0.0.1`）可模拟多名玩家（同源标签共享本地令牌）。

## 部署
- **Netlify**：仓库已含 `netlify.toml`（`npm run build` → `dist`），无需任何环境变量。
- **GitHub Pages**：`.github/workflows/deploy.yml` 在推送到 `main` 时跑测试、构建并发布（仓库 Settings → Pages → Source 选 GitHub Actions）。
- 用手机浏览器打开网址，「添加到主屏幕」即可作为 PWA 使用。使用 hash 路由与相对路径，子路径部署无需额外配置。

## 实测步骤（12 人）
1. 房主打开应用 → 输入昵称 → 创建房间，展示 QR Code；其余 11 人扫码或输入代码加入。
2. 12 人全部「准备」后房主点「开始游戏」；每人点「查看身份」并「我已记住身份」。
3. 之后按手机提示操作：夜晚（狼人→预言家→女巫）→ 天亮 → 首日警长竞选 → 发言 → 归票/投票……直到结算页显示完整身份与记录。
4. 玩家可中途刷新或断网重连，座位与进度会恢复。

## 规则与默认约定（规则未明确处）
- **白痴**：规格中「翻牌免于放逐」与「翻牌后死亡」互相矛盾，采用详细规则：被放逐后可选择翻牌（公开身份）或不翻牌，**两种选择均出局**，计入「屠神」。
- 猎人同夜既被刀又被毒 → 视为毒杀，不能开枪；被救者再被毒仍死亡。猎人开枪可选择不开枪、不能选自己。
- 胜负在每次死亡结算后立即检查（夜间、放逐、开枪、毒杀、翻牌）；若游戏已分胜负，猎人不再开枪。同时满足时**好人（狼全灭）优先**。
- 警长竞选：全员报名/不报名 → 候选人选择退水 → 最终候选人 ≥2 才投票；唯一候选人直接当选；**退水者不参与投票**，候选人可投其他候选人但不能投自己；允许弃票。平票时仅平票候选人参选，平票者不投票，再平票则无警长。
- 警长：出局时先结算猎人，再移交（或撕毁）警徽；归票后警长票 1.5，不归票为 1。警长选顺时针/逆时针发言（从警长下一位开始、警长最后发言）；无警长时按 1→12。
- 放逐投票：存活者一人一票、可投自己、可弃票；全部提交后才公布票型。平票 → 平票者依次发言 → 其余玩家重投；再平票本轮无人出局。
- 「跳过当前发言者」可由任一存活玩家触发，用于发言者离线时防止卡死；倒计时仅供参考。
- 状态机含规格全部状态；`DAY_ANNOUNCEMENT`、`NIGHT_RESOLUTION`、`VICTORY_CHECK` 在同一次结算内瞬时完成，另加 `SHERIFF_HANDOVER`。公共视图中夜晚统一显示为 NIGHT，避免泄露谁在行动。
- 游戏结束后房主可「再来一局」回到等待室。

## 自动化测试
`npm test`（Vitest，47 项）覆盖：加入/满员/开局校验、4狼4神4民分配、信息隔离（发给每位玩家的视图序列化后不含他人身份/令牌）、狼人刀口与平票、预言家、女巫（不可自救/不可双药/解药后不见刀口/只死一次）、猎人开枪条件、白痴翻牌、警长竞选与 1.5 票权重/平票/警徽移交与撕毁、放逐平票、屠神/屠民/狼全灭及优先级、非法请求（错阶段/非本角色/死亡/重复提交）、房主存档恢复，以及 **300 局随机机器人整局模拟**。
