# 狼人杀自动法官（12 人 · 预女猎白）PWA

12 位玩家各用手机加入同一个房间，由系统担任法官：随机发身份、自动主持夜晚、结算死亡、统计投票、判定胜负。无需真人法官和实体牌，**创建房间的人也看不到别人的身份**。

不使用 Supabase；后端是 **Netlify Functions + Netlify Blobs**。

## 架构
```
手机 ──HTTPS 长轮询/POST──► Netlify Function (netlify/functions/game.mts)
                                   │  规则引擎 shared/engine + 请求处理 server/handler.ts
                                   ▼
                           Netlify Blobs（强一致，条件写入）
                           rooms/<房间码> = { version, state(含全部身份) }
                           seen/<房间码>  = 在线心跳
```
- **完整状态与身份底牌只存在 Netlify Blobs 里**，客户端读不到。每次请求后端从 Blobs 读出状态，返回「公共视图 + 请求者自己的私人视图」，其他任何信息都不会下发。创建者和其他玩家权限完全相同。
- **并发控制**：每次操作 = 读取（带 etag）→ 规则引擎校验并计算 → `setJSON(..., { onlyIfMatch: etag })` 条件写入；写入冲突则退避重试。因此 12 人同时提交不会丢操作，重复点击/重复请求由状态机拒绝（`LOCKED`），不会重复结算或重复消耗药剂。
- **身份令牌**：每台手机在本机生成随机令牌（`localStorage`），后端只保存其 SHA-256 哈希；刷新页面后凭令牌恢复座位与进度。
- **实时**：客户端长轮询（`since=<版本>`，服务端最多挂起约 7 秒，有变化立即返回）；提交操作后立即刷新。
- **随机**：身份洗牌、平票随机均使用 `crypto.getRandomValues`（拒绝采样，无模偏差），在后端执行。

| 部分 | 方案 |
|---|---|
| 前端 | React + TypeScript + Vite + Tailwind CSS，PWA（`vite-plugin-pwa`） |
| 规则引擎 | `shared/engine/`：纯 TypeScript 有限状态机（`types.ts`、`engine.ts`、`views.ts`） |
| 后端 | `server/handler.ts`（与平台无关）+ `netlify/functions/game.mts`（Blobs 适配器） |
| 本地开发 | `vite.config.ts` 内置开发用 API 插件（内存存储，无需 Netlify CLI） |

## 本地运行
```bash
npm install
npm run dev      # http://localhost:5173（API 由内置插件用内存存储模拟）
npm test         # 自动化测试
npm run build    # 类型检查 + 生产构建（含 PWA）
```
本地同源标签共享同一令牌；模拟多名玩家请用不同来源（`localhost` / `127.0.0.1`）或隐私窗口。

## 部署（Netlify）
仓库含 `netlify.toml`（`npm run build` → `dist`，`netlify/functions` 自动识别）。Netlify Blobs 在 Functions 中自动可用，**无需任何环境变量或额外配置**。
用手机浏览器打开网址，「添加到主屏幕」即可作为 PWA 使用。

线上实测（12 个机器人经真实接口并发打完整局）：
```bash
LIVE_URL=https://lrs-app.netlify.app npx vitest run tests/live.test.ts
```

## 12 人实测步骤
1. 任一玩家打开应用 → 输入昵称 → 创建房间，展示 QR Code；其余 11 人扫码或输入代码加入。
2. 12 人全部「准备」后创建者点「开始游戏」；每人点「查看身份」并「我已记住身份」。
3. 之后按手机提示操作：夜晚（狼人→预言家→女巫）→ 天亮 → 首日警长竞选 → 发言 → 归票/投票……直到结算页显示完整身份与记录。
4. 玩家可中途刷新或断网重连，座位与进度会恢复。

## 规则与默认约定（规则未明确处）
- **白痴**：规格中「翻牌免于放逐」与「翻牌后死亡」互相矛盾，采用详细规则：被放逐后可选择翻牌（公开身份）或不翻牌，**两种选择均出局**，计入「屠神」。
- 猎人同夜既被刀又被毒 → 视为毒杀，不能开枪；被救者再被毒仍死亡。猎人开枪可选择不开枪、不能选自己。
- 胜负在每次死亡结算后立即检查（夜间、放逐、开枪、毒杀、翻牌）；若游戏已分胜负，猎人不再开枪。同时满足时**好人（狼全灭）优先**。
- 警长竞选：全员报名/不报名 → 候选人选择退水 → 最终候选人 ≥2 才投票；唯一候选人直接当选；**退水者不参与投票**，候选人可投其他候选人但不能投自己；允许弃票。平票时仅平票候选人参选，平票者不投票，再平票则无警长。
- 警长：出局时先结算猎人，再移交（或撕毁）警徽；归票后警长票 1.5，不归票为 1。警长选顺时针/逆时针发言（从警长下一位开始、警长最后发言）；无警长时按 1→12。
- 放逐投票：存活者一人一票、可投自己、可弃票；全部提交后才公布票型。平票 → 平票者依次发言 → 其余玩家重投；再平票本轮无人出局。
- 「跳过当前发言者」可由任一存活玩家触发，用于发言者离线时防止卡死；倒计时仅供参考。
- 状态机含规格全部状态；`DAY_ANNOUNCEMENT`、`NIGHT_RESOLUTION`、`VICTORY_CHECK` 在同一次结算内瞬时完成，另加 `SHERIFF_HANDOVER`。公共视图中夜晚统一显示为 NIGHT，避免泄露谁在行动。
- 游戏结束后创建者可「再来一局」回到等待室。

## 自动化测试
`npm test`（Vitest）覆盖：加入/满员/开局校验、4狼4神4民分配、信息隔离、狼人刀口与平票、预言家、女巫（不可自救/不可双药/解药后不见刀口/只死一次）、猎人开枪条件、白痴翻牌、警长竞选与 1.5 票权重/平票/警徽移交与撕毁、放逐平票、屠神/屠民/狼全灭及优先级、非法请求；**300 局随机整局模拟**；后端接口测试（12 人并发准备、乐观锁冲突、重复提交、创建者看不到他人身份、响应不含令牌、存储只存令牌哈希、12 机器人经 HTTP 并发打完整局）。

## 已知限制
- 尚未用 12 台真实手机跑完整一局（已用线上接口 + 机器人验证流程）。
- 令牌存在浏览器本地；清除数据或换浏览器后无法找回座位。
- 无超时机制：玩家离线时夜间/投票会等待其回来（系统不替玩家决策）。
- 房间数据不会自动清理（Blobs 中每房间约几十 KB）。
- 能直接访问 Netlify 后台的站点所有者可以在 Blobs 中读到身份底牌——这是任何托管后端的固有前提。
